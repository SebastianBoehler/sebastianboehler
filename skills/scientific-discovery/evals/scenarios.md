# Behavioral scenarios

Use one or more cases for an independent forward-test. Give the agent the case and the skill,
not the evaluation rubric. Ask for the requested artifact without running external experiments.
These cases are artificial test fixtures, not scientific measurements.

## A. A plateau in physical design

User request: “We have another overnight budget. Map what we can still change and prepare the next
wave. We have done hundreds of runs and the previous agent says the space was thoroughly explored.”

Raw facts:

- Goal: minimize a public simulator's noise objective under its physical feasibility constraints.
- The official interface accepts a valid optical graph and element parameters. No fixed graph is required.
- The current best code fixes a six-element topology chosen on day one and optimizes 12 continuous values.
- The last 250 runs changed seeds, bounds and optimizer settings within that topology.
- Five named lanes use different optimizers on the same encoding. Their best feasible losses differ by <0.2%.
- A past seventh-element experiment failed an import before producing a feasible simulator call.
- Six compute-hours remain. The simulator and current candidate are reproducible. No new paid API is authorized.

Deliver a compact solution-space audit and three budgeted experiment cards. Distinguish preparation
from executed coverage. Do not invent results or change the official objective.

## B. A positive result with integration limits

User request: “A new method improved by one point. Combine it with our best system and estimate our rank.”

Raw facts:

- The incumbent's held-person development accuracy is 76%; its external score is 82%.
- The new method improves its own weak decoder from 43% to 44%, using all eight permitted delivery orders.
- Its 80% person/order interval for the paired effect is [+0.3,+1.7] points.
- An earlier integration supplied only new posteriors; later template stages kept old features.
- The test labels and current external leaderboard are not available in this session.
- Public data support person-disjoint selection. Evaluation state must reset between sessions.

Deliver the supported conclusion, competing explanations, and a minimal full-system test. State which
rank statements the evidence supports. Do not upload anything.

## C. Fresh contexts and unavailable providers

User request: “Use another model/provider to get genuinely different approaches and reset the team.”

Raw facts:

- One provider is available through the current tools, with fresh-context workers.
- No second provider is configured, and no new spending or data sharing is authorized.
- The current handover calls neural methods “closed”; the only recorded test used one tiny model alone.
- Two running jobs depend on source-locked snapshots and must finish.
- The project requires preserving its scientific ledger and reading the current factual contract.

Deliver a concrete available workflow and a minimal proposer brief. Identify what a reset would
actually retain or withhold, and what cannot currently be executed.

## D. Evolving the skill without overgeneralizing

User request: “Update the skill so this does not happen again.”

Raw facts:

- In one small image benchmark, a larger model lost 0.2 points on a single seed.
- The user had asked to compare several representation families, but every implementation used the same embedding.
- The agent's report said “we explored all architectures and larger models are closed.”
- The global skill is in a public repository; detailed project data are private.

Deliver a surgical proposed skill revision, a deidentified evidence entry and a behavioral regression
case. State what the one experiment does and does not establish. Do not publish private data.
