# Clarify intent

Inspect the request, current decisions, and authoritative sources before asking. Derive requirements
from the applicable instructions, documentation, rules, or code contracts. Identify their sources and
which limits are binding, agreed project choices, or assumptions. Challenge assumptions with evidence.

Propose an outcome and an observable success check. For consequential ambiguity, ask a short batch of
decision-relevant questions before committing to the affected approach. Explain what each answer
would change and give a recommendation when possible. Keep independent, reversible work moving.
Keep plausible interpretations open until a source or user decision resolves them. Resolve conflicts
with the person who can decide them.

Use the existing plan for work that needs a durable record. Keep the deliverables, constraints, and
success checks current. When the user changes direction, identify which checks or work need to change
and tell affected contributors. Proceed within existing authorization without a separate plan approval.
