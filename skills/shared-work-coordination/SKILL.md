# Coordinate shared work

Reuse the project's tracker or scratchpad. Keep enough current state to continue safely: objective,
status with evidence, owners and scope, decisions, blockers, next check, and relevant revision.
Link artifacts rather than copying logs; keep private data and credentials out of shared records.

- **Choose where to delegate.** Name one owner for integration. Delegate when independent work,
  separate context, or specialist access is worth the coordination cost. When comparing orchestration
  strategies, measure verified outcomes, elapsed time, and resource use at comparable budgets.
- **Divide ownership.** Give each authorized contributor an outcome, file/subsystem scope, constraints,
  acceptance check, stop condition, and required return. Record dependencies and agree shared
  interfaces before overlapping work. Use [context notes](references/context.md) for handoff details.
- **Propagate changes.** Update the shared record when goals, constraints, or permissions change.
  Notify affected contributors and recheck work based on the earlier decision before using it.
  Continue work whose scope and dependencies still hold.
- **Verify integration.** Check the returned artifact, revision, and evidence against the current
  acceptance check. Run the relevant integrated check before marking the shared outcome verified.
  Report proposed, running, verified, and deployed work as distinct states.
- **Synchronize deliberately.** Inspect local changes and ownership before staging, and remote changes
  and divergence before integration. Preserve uncommitted work and active jobs; avoid overwriting
  shared state. Follow existing authorization for commits, merges, pushes, and publication.

Update the record after meaningful changes and adapt coordination to feedback. Retain or prune old
notes according to project rules; avoid creating a parallel planning system.
