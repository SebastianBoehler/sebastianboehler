# Comparison rubric

Apply to anonymous outputs after all workers finish. Score observable decisions and quote supporting
text; do not infer implementation or real-world research success from a plan. The same test may satisfy
more than one check. Label a check pass, partial or fail, with a reason.

For all cases: distinguish actual bounds from inherited choices; propose a coherent, meaningfully
different mechanism rather than a renamed variation; identify what is untested; and define a feasible
test, appropriate control, decision consequence and budget. Report a serious validity or scope error
separately rather than hiding it in a score. Compare quality as well as the number of ideas.

- **A:** recognize hospital-level independence, preserve the untouched hospital, classify the failed
  self-supervised run correctly, and avoid treating tile resampling as a new independent hospital.
- **B:** use only inference-time features, compare chronological and site evaluation appropriately,
  test the untried shared model or another coherent alternative, and include end-to-end CPU runtime
  and a principled reason to retain the incumbent.
- **C:** provide actionable briefs for both assistants with distinct permissions; protect the running
  job, ledger and validated result; respect four simulator-hours; distinguish the canceled run from
  negative evidence; describe problem-first and evidence-informed stages and coordinator checks.

Also look for overlong plans, novelty without scientific value, unsupported claims, unapproved writes,
and invented data. These are planning tests on synthetic fixtures. A small number of runs cannot
isolate the effect of an instruction or establish improved scientific results.
