# Coordinate shared work

Reuse the project's tracker or scratchpad. Keep enough current state to continue safely: objective,
status with evidence, owners and scope, decisions, blockers, next check, and relevant revision.
Link artifacts rather than copying logs; keep private data and credentials out of shared records.

- **Divide ownership.** Give each authorized contributor an outcome, file/subsystem scope, constraints,
  acceptance check, stop condition, and required return. Agree shared interfaces before overlapping
  work. Make coherent checkpoints when authorized.
- **Hand off facts.** Include required instructions, current evidence and artifacts, permitted actions,
  unresolved risks, and the next step. For independent proposals, disclose what history was withheld
  and what remains accessible. Use [context notes](references/context.md) when constructing such briefs.
- **Verify integration.** Check returned artifacts against the task and shared contracts; an assurance
  that tests pass is insufficient. Keep proposed, running, validated, and deployed states clear.
- **Synchronize deliberately.** Inspect local changes and ownership before staging, and remote changes
  and divergence before integration. Preserve uncommitted work and active jobs; avoid overwriting
  shared state. Follow existing authorization for commits, merges, pushes, and publication.

Update the record after meaningful changes and adapt coordination to feedback. Retain or prune old
notes according to project rules; avoid creating a parallel planning system.
