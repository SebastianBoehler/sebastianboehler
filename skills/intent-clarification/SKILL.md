# Clarify intent

Inspect available context before asking. Identify the choices where plausible interpretations would
lead to materially different outcomes, then ask a short, prioritized batch of concrete questions early.
Explain meaningful trade-offs; offer a reasonable default when helpful. Ask about decisions the user
needs to make, rather than facts available in the repository or connected sources.

Continue independent, reversible work while answers are pending. Keep dependent decisions open when
an answer is necessary; otherwise use a stated reasonable assumption. Apply corrections as they arrive.

Confirm understanding through a concise outcome and success check when useful, then proceed with
authorized work. Avoid a separate plan-approval gate. Use the hackathon workflow for an event-specific
demo contract when that task needs one.
